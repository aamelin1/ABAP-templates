# Шаблон заметки

Каждая заметка базы — один md-файл на одну тему, с YAML-frontmatter в начале.
Frontmatter кормит генератор оглавлений (`tools/build_llms_txt.py`): из него
собираются строки `llms.txt` (для ИИ) и оглавление `README.md` (для людей).
Текст после frontmatter — обычный markdown для человека.

## Шаблон для копирования

```markdown
---
title: <Название, понятное вне контекста папки>
keywords: <ключ1>, <ключ2>, <термин RU>, <term EN>, ...
status: ok
summary: <Одна фраза о содержании — опционально>
source:
  - 90-source-code/<файл>.abap
---

# <Тот же title>

<Текст заметки.>
```

## Правила именования файла

- Латиница, lowercase, дефисы: `f110-setup-and-errors.md`.
- Без пробелов, кириллицы и подчёркиваний — имя попадает в raw-URL.
- Файл лежит в папке своего раздела (`10-fi/`, `50-abap/`, ...) — раздел
  определяется путём, в frontmatter не дублируется.

## Поля

### `title` — обязательное

Человеческое название; оно же текст ссылки в обоих оглавлениях.
Должно быть понятно **вне контекста папки** — в llms.txt строки разных
разделов читаются подряд.

- Плохо: `Настройка и ошибки`
- Хорошо: `Платежная программа F110 — настройка и типовые ошибки`

### `keywords` — обязательное

Поисковый индекс заметки: ассистент находит её, сопоставляя вопрос
пользователя со строкой llms.txt, которая состоит из title + summary +
keywords. Что здесь есть — то находится; чего нет — не существует.

Что включать:

1. **Коды транзакций**: `F110`, `OB52`, `MIRO`, `FBZP`.
2. **Таблицы**: `REGUH`, `T001B`, `BSEG`.
3. **Программы / ФМ / классы / BAdI**: `SAPFPAYM`, `FAGL_COFI_ACCIT_MOD`.
4. **Номера сообщений об ошибках и SAP Notes**: `AY163`, `FMUP047`,
   `Note 362037` — самые точные ключи: расследования часто начинаются с них.
5. **Термины парой RU + EN** для всего концептуального:
   `платежный прогон, payment run`, `периоды проводки, posting periods`.
   Это решение кросс-языкового поиска — не пропускать.

Ориентир: **5–15 ключей**. Меньше трёх — заметку не найти; больше двадцати —
строка забивает оглавление шумом. Не включать: слова, уже стоящие в title
(они и так в строке); общие слова без различительной силы (`SAP`, `настройка`,
`ошибка` по отдельности).

### `status` — обязательное

Управляет генератором:

| Значение | Поведение |
|---|---|
| `ok`    | Заметка в llms.txt и README-оглавлении |
| `draft` | В оглавлениях с пометкой *(черновик)* — черновик с правильными keywords полезнее отсутствия |
| `todo`  | Заглушка без содержания; в оглавления **не** попадает |

Миграция старых меток: «(to do)» → `todo`; «(перевести)», «⚠️ Черновик» → `draft`.

### `summary` — опциональное

Одна фраза о содержании. Если задано — идёт в строку llms.txt перед
keywords. Заполнять, когда title не раскрывает содержание: разборы
инцидентов, «истории расследований», заметки-сравнения.

### `source` — опциональное

Список относительных путей (от корня репы) к связанным ABAP-исходникам
в `90-source-code/`. Генератор превращает их в raw-URL и дописывает в строку
llms.txt — ассистент вытягивает заметку и код за одну итерацию.

Правило владения: **у каждого файла в `90-source-code/` должна быть ровно
одна заметка-владелец**, ссылающаяся на него через `source`. Сиротский код
в оглавления не попадает. Метаданные внутри ABAP-файлов не ведутся.

## Правила текста заметки

- Один файл — одна тема, размер, читаемый целиком (~до 300–500 строк);
  простыни делить на несколько заметок.
- **Суть — текстом.** Картинки web_fetch не читает: скриншот — только
  иллюстрация, вся необходимая информация дублируется словами.
- Картинки лежат в `img/` своего раздела; внешние вложения (URL на
  GitHub-attachments) затягивать в репо.
- Внутренние ссылки на другие заметки — относительные (для GitHub/Obsidian);
  в llms.txt пути к заметкам и так абсолютные.
- Без специфики работодателя: имена систем/хостов, логины, номера
  транспортов, детали конфигурации компании в публичную базу не попадают.

## Полный пример

```markdown
---
title: Платежная программа F110 — настройка и типовые ошибки
keywords: F110, payment run, автоматические платежи, SAPFPAYM,
  варианты формата, payment medium format, REGUH, REGUP, DME,
  платежный прогон, FBZP, банковские платежи
status: ok
summary: Настройка F110 с нуля, чек-лист FBZP и разбор типовых ошибок прогона
source:
  - 90-source-code/zfi_payment_example.abap
---

# Платежная программа F110 — настройка и типовые ошибки

## Предпосылки

Перед запуском F110 должна быть выполнена настройка в FBZP...

## Чек-лист настройки

...

## Типовые ошибки

### Прогон не создаёт носитель платежа

Проверить, что для формата существует вариант программы SAPFPAYM
в целевой системе...
```

Строка, которую генератор соберёт из этого frontmatter:

```markdown
- [Платежная программа F110 — настройка и типовые ошибки](https://raw.githubusercontent.com/aamelin1/ABAP-templates/main/10-fi/f110-setup-and-errors.md): Настройка F110 с нуля, чек-лист FBZP и разбор типовых ошибок прогона — F110, payment run, автоматические платежи, SAPFPAYM, варианты формата, payment medium format, REGUH, REGUP, DME, платежный прогон, FBZP, банковские платежи · код: [zfi_payment_example.abap](https://raw.githubusercontent.com/aamelin1/ABAP-templates/main/90-source-code/zfi_payment_example.abap)
```
